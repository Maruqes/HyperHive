# Btrfs ticket review

BR01 and BR02 have implementation changes but require coordinator review and browser verification before acceptance.

Backend files: `slave/btrfs/helpers.go`, `slave/btrfs/btrfsGRPC.go`, `slave/btrfs/btrfs.go`, `slave/btrfs/raid_eligibility_test.go`. Frontend files: `app/btrfs-raids.tsx`, `utils/btrfs-usage.ts`, `tests/btrfs-usage.test.js`.

The free endpoint filters the agent inventory on `Mounted`; it previously included all lsblk types because the RPC used `GetAllDisks(true)`. It now returns positive-size whole disks only. The agent excludes zram even when lsblk reports TYPE=disk, and marks Btrfs signatures, mounted and swap descendants, and mapped descendants as occupied. If usage discovery fails or omits a disk, inventory still returns it as unavailable; this preserves SMART and host inventory while failing closed for RAID selection. Create, add and replace RPCs recheck candidate paths against current inventory. Add checks mounted state before signature wiping. Existing direct Go loop-device integration fixtures are not changed. All-disk inventory also serves SMART API callers, so excluding zram, non-disk and zero-size devices is a shared behavior change. Creation rejects invalid names and profiles, empty and duplicate device lists, and checks known label conflicts before wiping. GetAllFileSystems errors stop creation before wiping; its existing empty-output behavior can still conceal unavailable discovery. Validation is point-in-time and cannot eliminate a device changing state between inspection and mutation.

Capacity rows retain existing units and selectable full UUIDs, and show labeled usage when values are valid, including zero used; invalid values do not generate a bar. The details view uses the same calculation.
