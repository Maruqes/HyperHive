## Contract: list_isos
- Sources: master/api/isos.go getAllISOs/setupISOAPI; master/db/isos.go ISO/GetAllISOs; master/services/nfs.go CanFindFileOrDirOnAllSlaves.
- No inputs, no body; authenticated GET /isos/ returns HTTP 200 JSON array (empty []).
- Objects use exact capitalized Id, MachineName, FilePath, Name; available_on_slaves maps machine names to booleans. Preserve unknown response fields and exact JSON integers.
- Availability is a best effort per-connected-slave probe; false may mean missing file or probe failure. This is no guarantee of successful downloads. Database failure returns 500.
- Read-only, idempotent, nondestructive. Reject unknown arguments, malformed response types, null objects/array; preserve false and empty maps.

## Contract: start_iso_download
- Sources: master/api/isos.go downloadIso; master/services/nfs.go DownloadISOAsync; master/nfs/nfs.go DownloadISO; slave/nfs/setupgrpc.go DownloadIso; slave/nfs/nfs.go DownloadISO/downloadFile; slave/go.mod grab v3.0.1; pinned grab client.go checksumFile/request.go SetChecksum.
- Required url and iso_name strings ending exactly in .iso; required positive nfs_share_id integer. MCP safety bounds require an absolute HTTP(S) URL without credentials/fragment and a leaf filename without slash, backslash or NUL. Backend suffix-only validation permits filesystem escape through filepath.Join, so MCP intentionally rejects path inputs. Send supported values unchanged.
- HTTP 202 JSON {"status":"started"} means initiation only. No task identifier or completion endpoint is provided. Async download, sync and registration can each fail later; notifications report outcomes. Do not retry automatically or fabricate a completed ISO.
- Existing ISO name returns 409; missing share 404; disconnected slave 500; malformed request/suffix 400.
- Side effects: writes a new ISO file, syncs, registers ISO, emits notifications/progress. Master async helper has no rollback or deletion; partial files may remain on failure. Slave refuses existing destination. Grab deletion is only checksum mismatch cleanup after explicit SetChecksum(..., true); this call path never configures a checksum/hash, so that deletion branch is unreachable.
- Non-read-only, non-idempotent, nondestructive under the reviewed deletion policy. Expose the full initiation contract only, with acceptance language and no completion claim.
