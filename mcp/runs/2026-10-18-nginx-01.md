## Contract cards

### list_certificates
- Mapping: GET /certs/list
- Required input shape: `{}` (values are disposable examples, not defaults).
- List certificate metadata visible to the configured account, preserving the complete HyperHive response objects. Takes no arguments.

### list_dns_providers
- Mapping: GET /certs/dns-providers
- Required input shape: `{}` (values are disposable examples, not defaults).
- List supported DNS providers, names and credential-format templates. Templates are not configured credentials. Takes no arguments.

### download_certificate
- Mapping: POST /certs/download
- Required input shape: `{"id":42}` (values are disposable examples, not defaults).
- Download a certificate archive. The returned base64 data can contain private keys: treat it as secret. Preserves content type and disposition; never writes files. Maximum API response 16 MiB. Timeout three minutes, honoring cancellation. Read-only despite POST.

### renew_certificate
- Mapping: POST /certs/renew
- Required input shape: `{"id":42}` (values are disposable examples, not defaults).
- Renew a Let's Encrypt certificate. Only the API decides provider eligibility. Waits for the API response, with an eleven-minute timeout covering its ten-minute downstream operation. Cancellation or timeout can leave work running in HyperHive: inspect certificate state before retrying. Returns acceptance only, not certificate data. No automatic retry.

### list_access_lists
- Mapping: GET /access-lists/list
- Required input shape: `{}` (values are disposable examples, not defaults).
- List expanded access lists, including owner, authentication items and network clients. Preserve API masking and all returned fields. Takes no arguments.

### create_access_list
- Mapping: POST /access-lists/create
- Required input shape: `{"name":"office","satisfy_any":false,"pass_auth":false,"items":[{"username":"fixture-user","password":"fixture-password"}],"clients":[{"directive":"allow","address":"10.0.0.0/8"},{"directive":"deny","address":"all"}]}` (values are disposable examples, not defaults).
- Create an access list with explicit name, satisfy_any, pass_auth, authentication items and client rules. Empty arrays are supported. Passwords are sensitive; the API may mask them on listing. No existing entries are edited. Returns acceptance only; no created ID is returned and no automatic retry occurs.
